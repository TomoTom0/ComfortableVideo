## Bug Fixes

- オプションページの設定が拡張機能の挙動に反映されない問題を修正
  - 原因: content script が chrome.storage を一切読み込んでおらず、ホバー検出時間・コントロール無効化時間は定数 (2000ms / 3000ms) で動作していた。設定更新メッセージ (settingsUpdated) のハンドラは無処理で、解除ボタンの透明度を更新する関数は空実装だった。実際に効いていたのは background が読むコンテキストメニュー表示の2項目のみで、残り9項目は保存されるだけで挙動に反映されなかった
  - 対応: content script に設定の読み込み・反映の仕組みを実装した。起動時の storage 読み込み、settingsUpdated メッセージ、chrome.storage.onChanged の3経路で最新の設定を保持し、タイマー時間 (hoverDetectionTime / controlsDisableTime)、一時停止中の即時有効化 (pausedControlsEnabled)、プレーヤー内ボタンの表示 (showInlineButton)、サイト別有効化 (enableYoutube / enablePrimeVideo / enableTTFC / enableAllSites)、解除ボタンの透明度 (exitButtonOpacity) を全て挙動へ反映する。現在のサイトが無効化された場合は快適モードを自動で解除し、ボタンも取り除く。あわせて、オプションページの「リセット」がコンテキストメニューへ追随するよう、background でも storage の変更を監視してメニューを作り直すようにした
  - 実ページ検証 (Chrome for Testing + 実際の YouTube / Prime Video / ローカルの汎用ページ): exitButtonOpacity を80にすると解除ボタンの computed opacity が 0.8 になり、20へ戻すとリロードなしで 0.2 へ追随することを確認。hoverDetectionTime を5000msにすると、下部ホバー後2.5秒ではコントロールが有効化されず5.7秒で有効化されることを確認 (従来の定数2000msでは2.5秒時点で有効化されていた)。controlsDisableTime を1000msにすると、汎用ページで動画から離れて約1.3秒で無効化されることを確認 (デフォルト3000msでは同タイミングで無効化されない)。pausedControlsEnabled を無効にすると、一時停止中のマウス移動では即時有効化されず、下部ホバーの検出時間経過後に有効化されることを確認。showInlineButton / enableYoutube を無効にすると YouTube にボタンが表示されなくなること、enableAllSites を無効にすると汎用ページでトグルしても有効化されないこと、enablePrimeVideo を無効にすると Prime Video で快適モードが自動解除され復元されることを確認した。enableTTFC はログインが必要なため実ページ検証は行わず、単体テストで担保する

- YouTube で快適モード中にウィンドウをリサイズすると快適モードが自動解除される問題を修正
  - 原因: リサイズハンドラが最大化済みの動画へ maximizeVideo を再実行し、#movie_player が body へ再追加される。その際の childList 削除記録を動画監視 (watcher) が「動画が削除された」と判定して解除していた (解除自体は無言で行われ、その後の属性記録が z-index チェックに触れて「YouTube側でスタイルが書き換えられたため自動解除」のログが出ていた)。あわせて再実行が元の位置情報とプレースホルダーを最大化後の状態で上書きし、復元情報も壊していた。実リサイズだけでなく合成 resize イベント1回でも再現することを実測で確認した
  - 対応: リサイズ時は最大化済みの動画へ maximizeVideo を再実行しない (表示サイズは CSS クラスの 100vw / 100vh で決まり、リサイズへ自動で追随する)。maximizeVideo 自体も冪等化し、最大化済みの場合は元の位置情報の再保存やプレースホルダーの再挿入を行わない (grace period 経由の再突入でも同じ保護が効く)。さらに watcher 側でも、バッチ適用後の時点で動画が文書内に残っている場合は付け替え (移動) とみなして解除しないよう、多重に防御した
  - 実ページ検証 (Chrome for Testing + 実際の YouTube、メディアロード済み): 1280x900 → 900x700 の実リサイズと復帰を行い、快適モードが維持され、プレースホルダーが1個のままであること、解除時にプレーヤーが元の位置へ復元されることを確認した。修正前は同じ条件 (メディアロード済みでの実リサイズ、合成 resize イベント) で自動解除が再現していた

- Prime Video で快適モードのトグルボタンがプレーヤーに表示されない問題を修正
  - 原因: 現行の Prime Video プレーヤー（React UI）では、従来の挿入先コンテナ `.atvwebplayersdk-hideabletopbuttons-container` が存在しない。上部ボタンは `.atvwebplayersdk-player-container` 内の行にボタン要素として並び、クラス名はハッシュ化されていて安定しないため、従来のセレクタでは挿入先を特定できなかった
  - 対応: 上部ボタンを左から並べ、ボタン間の最も大きな水平間隔を境界として右側クラスタ（字幕・音量・全画面等）を分け、その共通祖先であるボタン行を構造検索で特定し、その先頭へ挿入するようにした。プレーヤーの水平中央で分けないため、狭いプレーヤーで右側クラスタが中央を跨ぐ場合でも特定できる。従来セレクタはフォールバックとして維持する。ボタン行は UI 表示中のみマウントされるため、プレーヤー内へのボタン追加を MutationObserver で検出して挿入する経路もあわせて対応した
  - 実ページ調査 (Chrome for Testing + 実際の Prime Video、字幕つき無料特典映像): 現在のプレーヤーで上部ボタンが7個（左: 閉じる、右: 字幕・Mute・PiP・全画面・速度・メニュー）であることと、構造検索が右側6ボタンの行コンテナを一意に特定できることを実測した

- Prime Video で快適モード中に字幕が表示されない問題を修正
  - 原因: 現行の Amazon.co.jp プレイヤーは字幕を `.atvwebplayersdk-captions-overlay` として生成せず、プレイヤー階層内の `.atvwebplayersdk-captions-text` として描画する。そのため従来のオーバーレイ移動（body への移動と `comfort-mode-exempt` 付与）が発動せず、字幕要素の祖先チェーン全体が快適モードの z-index 上限（999998）で制限され、body 直下へ移動された動画（2147483646）の背面に回っていた
  - 対応: 字幕テキストの祖先にある位置決め（absolute / fixed）されたラッパー要素を検出し、オーバーレイと同じ扱いで body へ移動して `comfort-mode-exempt` と専用クラスを付与するようにした。専用クラスには固定配置と z-index 2147483647 を割り当て、ラッパー自身のインラインスタイル（幅・下端位置・中央寄せ）で配置が決まるようにした。快適モード解除時はラッパーを元の位置へ復元する
  - 実ページ検証 (Chrome for Testing + 実際の Prime Video、字幕つき無料特典映像): 同じ字幕キュー（t=217）で通常モードと快適モードを比較し、快適モードでも字幕が動画の前面に表示されることを画面キャプチャ（X 画面）で確認した。解除時に字幕ラッパーと動画が元の位置へ復元されることも確認した

- TVer など Video.js 系プレイヤーで快適モード中に字幕が表示されない問題を修正
  - 原因: 汎用経路では動画要素だけが body へ移動して全画面化し、字幕表示要素 `.vjs-text-track-display` が元のプレイヤーコンテナ内に残る。そのため字幕表示要素が快適モードの z-index 上限（999998）で制限され、body 直下へ移動された動画（2147483646）の背面に回っていた。字幕キュー自体は DOM に存在し続けるため、字幕データはあるのに見えない状態になっていた
  - 対応: 快適モード有効化時に `.vjs-text-track-display` を検出し、字幕オーバーレイの移動と同じ扱いで body へ移動して `comfort-mode-exempt` と専用クラスを付与するようにした。専用クラスには全面固定配置と z-index 2147483647 を割り当て、最大化された動画の前面に字幕を表示する。元の位置は要素ごとに記録し、快適モード解除時は各要素を元の位置へ復元する

- YouTube で快適モード中に動画をクリックしても再生/一時停止が切り替わらない問題を修正
  - 原因: 動画へのクリックが YouTube 自身のクリック処理（再生/一時停止トグル）と、拡張の `handleClick` の両方で処理され、二重にトグルして元の状態に戻っていた。下部20%のクリックでも YouTube 側のトグルが動作していた
  - 対応: クリックを capture フェーズで受け取り、対象が動画要素自身の場合は拡張側でのみ処理して伝播を止めるようにした。終了ボタンやカスタムコントロール等、動画以外の要素へのクリックは従来どおり素通りする
  - 実ページ検証 (Chrome for Testing + 実際の YouTube、快適モード有効): 上部クリックで再生/一時停止がちょうど1回ずつ反転することを確認。下部20%については、領域内125点を elementFromPoint で走査し、94点で動画要素自身がターゲットになることを実測した (残りはカスタムコントロールバーやボタン類が被覆する点)。動画要素自身がターゲットになる点 (動画矩形の左から18%、上から90%の位置) へ CDP の実マウスイベントでクリックを送り、実際の click イベントのターゲットが動画要素自身であること、再生状態が変わらないこと、ホバー検出 (2秒) より十分に速くコントロールが有効化されることを確認した

- 快適モードで一時停止した際に、字幕の下側がカスタムコントロールバーに重なって隠れる問題を修正
  - 原因: 字幕は画面下端付近（下端から90px）に表示され、カスタムコントロールバーは下端60pxに高さ約70pxで表示されるため、バー表示中は字幕の2行目がバーと重なっていた。コントロール表示中に字幕を逃がす仕組みが無かった
  - 対応: カスタムコントロールの表示状態を body の `comfort-controls-visible` クラスへ同期し、バー表示中は字幕要素を150px上へ逃がすようにした。`hidden` クラスの付け外しは `setCustomControlsHidden` に集約し、全ての切替経路（再生/一時停止、マウス監視、自動非表示）で同期する

- YouTube で快適モード中に字幕が表示されない問題を修正
  - 原因: YouTube 経路では #movie_player と内部の .html5-video-container の両方へ .comfort-mode-video-container（z-index 2147483646）が付与されるため、プレイヤー内に残る字幕コンテナ（.ytp-caption-window-container、z-index auto）が動画コンテナのスタッキングコンテキストの背面に回り、字幕が DOM に存在しても描画されなかった。あわせて、バー表示中に字幕を上へ逃がすオフセットの対象に YouTube の字幕コンテナが含まれておらず、字幕の矩形はバーと重なる位置関係だった（下側44px、2行字幕では2行目がバーの裏側）
  - 対応: 快適モード中は .ytp-caption-window-container へ字幕用の z-index（2147483647）を割り当ててプレイヤー内の動画より前面に出し、バー表示中（body.comfort-controls-visible）のオフセット対象へも追加して 150px 上へ逃がすようにした
  - 実ページ検証 (Chrome for Testing + 実際の YouTube、未ログイン、手動の英語字幕トラック): 修正前は快適モードで字幕が描画されないこと（字幕位置の要素積層で動画が字幕より前面）を実測した。修正後は、一時停止中（バー表示）は字幕が 150px 上がってバーとの重なりが無くなり（字幕下端とバー上端の間隔 106px）、再生中（バー非表示）は通常位置で字幕が動画の前面に表示されることを実測した。快適モード終了後の通常表示に変化が無いことも確認した

- Prime Video で快適モード中に字幕ラッパーが差し替えられると、古い字幕が固まったまま重なって表示され、解除時に復元失敗の警告が出る問題を修正
  - 原因: シーク等でプレイヤーが字幕ラッパーを差し替えると、body へ移動済みの旧ラッパーが残り続け、新しい字幕と重なって表示された。旧ラッパーは元の親も失われているため、解除時の復元にも失敗していた
  - 対応: 新しいラッパーを body へ移動する前に、現在の字幕テキストを含まない旧ラッパーのうち、元の親を失われているもの、または差し替え前の字幕を保持したまま残っているものを破棄するようにした。現在の字幕テキストの特定は、移動済みラッパー内のテキストを候補から外して行う。解除時の復元でも、差し替えで残っただけの要素は警告ではなく取り除くようにした（表示中の字幕そのものは従来どおり body に残す）

- Prime Video でプレーヤーUIの表示/非表示のたびにボタンの再挿入と「ボタン行が見つからない」ログが繰り返し出る問題を修正
  - 原因: Prime の UI は非表示時に上部ボタン行ごと取り除くが、監視側は行の取り除きを一律にボタン削除とみなして即時の再挿入を試み、行が無い間も「見つからない」ログを出し続けていた
  - 対応: ボタン行が見つからない場合は UI 非表示中の通常の状態として無言で何もしないようにし、削除検知時の再挿入試行は間隔を空けた再確認1回にまとめた。行が戻れば追加ノード側の監視が再挿入する
